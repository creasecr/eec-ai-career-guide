# eec-ai-career-guide

AI-powered class recommendation and career pathway guide prototype for EEC learning programs.

A responsive, ChatGPT-style web app that interviews a learner about their career interests,
experience level, industry, learning goals and preferred format, then recommends Energy Education
Center courses and builds a beginner to advanced learning pathway with registration links.

## Running locally

The app loads `courses.json` with `fetch`, so it must be served over HTTP rather than opened
directly from the file system:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

## Files

| File | Purpose |
| --- | --- |
| `index.html` | Chat shell: header/branding, message list, quick replies and composer |
| `styles.css` | Utility/energy branding, chat layout and mobile responsive rules |
| `app.js` | Conversation flow, answer interpretation, recommendation engine, rendering |
| `courses.json` | Course catalog plus the taxonomy (interests, levels, industries, goals, formats) |

Built with vanilla HTML, CSS and JavaScript - no build step and no dependencies.

## Course catalog

Each course entry drives the recommendation engine:

```json
{
  "id": "EEC-220",
  "title": "Solar Plus Storage Design and Commissioning",
  "level": "beginner | intermediate | advanced",
  "durationHours": 20,
  "formats": ["online", "in-person"],
  "interests": ["renewables"],
  "industries": ["construction"],
  "goals": ["certification"],
  "prerequisites": ["EEC-120"],
  "description": "...",
  "registrationUrl": "https://..."
}
```

Courses are scored against the learner profile (interest, industry, goal, format and level fit);
the pathway picks the strongest course at each level and pulls in any prerequisites so the steps
always read beginner to advanced.

## Future OpenAI integration

`AIService` in `app.js` isolates response generation from the UI. It ships with a local rule-based
provider and a prepared OpenAI provider:

```js
EECCareerGuide.AIService.configureOpenAI({
  proxyUrl: "/api/career-guide", // server-side endpoint that adds the API key
  model: "gpt-4o-mini"
});
```

Once a proxy URL is configured, summaries are generated by the model and automatically fall back to
the local provider if the request fails. API keys must stay server-side - never in the browser.
